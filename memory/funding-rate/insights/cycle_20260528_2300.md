## Smoking gun #1 — the tick universe's return labels are funding-only (no price)

`/tmp/tick_universe.parquet` = 2,135,533 rows × 26 cols. Columns are funding-derived only:
`rate, rate_abs, roll_mean_24, roll_max_abs_24, roll_std_24, rate_lag{1,6,24}, vel_{6,24}, fwd_cum_{1,4,8,24}, long_ret_{1,4,8,24}, short_ret_{1,4,8,24}`.

**There is NO price / spot / mark / close / open column anywhere** (verified: `[c for c in cols if any(x in c for x in price-tokens)] == []`). So a price/delta PnL is not merely omitted — it is structurally absent.

Verified exact identities across the full 2.14M-row set (corr = 1.000000, `np.allclose` True for k∈{1,4,8,24}):
```
short_ret_N  ≡  fwd_cum_N          (= Σ of next N funding rates; SHORT collects positive funding)
long_ret_N   ≡  −fwd_cum_N         (LONG collects negative funding)
```
Therefore `long_ret_N = −short_ret_N` **identically** — the two sides are zero-sum. The only "PnL" in the dataset is the funding transfer. **For ANY filter whatsoever, picking the side aligned with the funding sign yields a positive "return" by construction.** That is the entire mechanism behind every WR-100% "edge" in the catalog. There is no alpha in the data; there is only the funding rate re-labelled as profit.
