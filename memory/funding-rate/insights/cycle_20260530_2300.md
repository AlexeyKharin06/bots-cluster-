## Method

Wrote `/srv/bots/funding-rate/code/scripts/c2_basis_drift_okx_bitget.py` — a parallel-fetch adaptation of cycle 1700's `c2_basis_drift_bybit_gate_v2.py` for okx + bitget public klines APIs:

- **OKX**: `GET /api/v5/market/history-candles` with `instId=SYM-USDT` (spot) or `SYM-USDT-SWAP` (perp), `bar=1H`, `after=t1+1h`, `limit=100`. Returns newest-first; tuple format `[ts_ms, o, h, l, c, vol, volCcy, volCcyQuote, confirm]`.
- **Bitget**: `GET /api/v2/{spot|mix}/market/history-candles` with `symbol=SYMUSDT`, `granularity=1h` (spot) or `1H` (mix), `endTime=t1+1h`, `limit=200`. Mix requires `productType=USDT-FUTURES`. Returns oldest-first; tuple format `[ts_ms, o, h, l, c, vol, quote_vol]`.

12 workers (slightly less than cycle 1700's 16 to be polite to public APIs). Wall-clock fetch: okx 24s / bitget 18s — much faster than expected because of small N.

Replicated the cycle 1700 trigger generation:
- div ≥ THR_P99 = 0.0028 on c2_wide (1.09M rows)
- primary_ex = argmin funding
- DEDUP per (sym, primary_ex) at 24h
- Annotate `triggered_shorten` flag using `c2_shortenings.parquet` next-shortening lookup; if found within MAX_HOLD_H=24h, exit = shorten_ts + EXIT_AFTER_SHORTEN_H=4h, else exit = t0 + 24h
- For each event, fetch ±2h padded klines on perp + spot; entry = open of t0-aligned candle; exit = close of last candle ≤ exit_ts
- PnL = fund_collected + (perp_ret − spot_ret) − RTC (40bp round-trip both legs)
- fund_collected pulled from multi_ex_funding_180.parquet, summing rates posted in (t0, exit_ts] window with sign-flip (LONG-perp on negative funding side receives rates)

(Then a minor post-hoc bug fix: the `triggered_shorten` column came back from parquet as int-after-mixed-NaN, so analysis was redone via `/tmp/c2_ob_analyze.py` with explicit `astype(bool)` cast. Result data identical.)

Adding okx (per-venue Sh 0.76 > pool Sh 0.35) DID NOT degrade pool Sharpe — it stayed essentially flat at 0.36. Bitget (per-venue Sh −0.07 < pool Sh 0.36) degraded BOTH mean and Sharpe.

**Promoted Meth #33 (2/2 corroboration, both signs)**:
> When expanding a multi-venue funding strategy, estimate per-venue Sharpe on a held-out window. Adding a venue with per-venue Sharpe ≥ current pool Sharpe preserves pool Sharpe; adding a venue with per-venue Sharpe < current pool Sharpe degrades both mean (if per-venue mean is also weak) and Sharpe (if per-venue tail is heavy). Apply as a venue-acceptance gate, NOT a universe-cap rule.

Filed as **Methodology #33 FINAL** (was CANDIDATE 1/2 in cycle 1700).
