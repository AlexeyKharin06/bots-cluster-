# Cycle 20260524_1100 — Methodology #14 retroactive on PYUSD events: HYPOTHESIS REJECTED, NEW boundary discovered

## TL;DR

Executed BRIEF cycle 0500 next-cycle plan #2: "Methodology #14 retroactive on PYUSD events; predict SOLO outperforms CONFIRMED." Result: **the prediction is REFUTED**. On 24 PYUSD events (4 bybit + 20 kucoin), SOLO subset (n=19) mean +0.489% / WR 100% / hold_median 8.4h ≈ CONFIRMED subset (n=5) mean +0.481% / WR 100% / hold_median 8.3h — gap +0.008pp = pure noise. No PnL discrimination, no WR discrimination, no hold-time discrimination.

**Mechanistic interpretation**: Methodology #14 (cycle 2300) was empirically discovered on USDe + USDD + TUSD + USDP + FDUSD universe. The shared structural feature of that universe is **distributed-redemption arb pathways** — synthetic stables redeem on-chain (USDe/USDD via Ethena/Justin Sun bridge); blue-chip fiat stables redeem via venue-specific dollar rails (TUSD/USDP/FDUSD). When pressure hits multiple venues simultaneously, the per-venue redemption channel is overloaded → slow revert. SOLO depegs reflect single-venue orderbook imbalance → fast natural reversion.

**PYUSD breaks this pattern**: PayPal/Paxos operate a unified, regulated B2B redemption desk that arbs are run against centrally. The redemption channel is venue-independent. So **whether a depeg shows on 1 venue or 2 makes no difference** to the arb-closure speed — both revert in ~8h on PYUSD. The signal value of cross-venue coincidence vanishes when the redemption pathway is centralized at issuer.

**Decision matrix update**: H3_DEPEG_PAPER_SOLOFLAG should apply ONLY to {USDe, USDD, TUSD, USDP, FDUSD, USDC} subset (the original H3 universe where Meth #14 was discovered). **For PYUSD events the SOLOFLAG filter would discard 21% of throughput (5/24) at zero PnL/WR benefit.** This is a stable-class-conditional filter, not a universal one.

**New Methodology #16 candidate**: Cross-venue coincidence signal value depends on redemption-channel architecture. If the dominant arb pathway is centralized at issuer (B2B desk), SOLO≈CONFIRMED. If the dominant pathway is venue-distributed (per-venue dollar rails or on-chain bridges), SOLO outperforms.

## Why does Meth #14 not apply here? — mechanism analysis

Parent H3 universe (cycle 2300 / cycle 1700) where Meth #14 was discovered:
- USDe (Ethena): synthetic stable, USDe ↔ USD via on-chain Ethena protocol mint/redeem at fixed rate
- USDD (TRON): synthetic stable, USDD ↔ USDT via on-chain bridge
- TUSD/USDP/FDUSD/USDC (Paxos/Circle/Paxos/Circle): fiat-backed, redeem via per-venue dollar rails to issuer banks

In all 6 of those: the dominant arb pathway is **venue-distributed**:
- For USDe: arbers redeem locally (on the venue that's depegged) then bridge cross-venue
- For USDD: same TRON-bridge logic
- For TUSD/USDP/FDUSD: arbers go through whichever banking rail is fastest (different per venue)

When pressure hits 2+ venues simultaneously → multiple arb queues form simultaneously → systemic pressure → slow revert → Meth #14 verdict.

**PYUSD is different.** Paxos operates a unified B2B redemption desk that handles institutional arbs directly with Paxos balance sheet. The desk:
- Has uniform arb capacity regardless of venue
- Doesn't queue per-venue
- Closes spreads in ~hours for any depeg ≥20bp

So whether a PYUSD depeg shows on 1 venue or 2, **the arb response is identical**. SOLO and CONFIRMED revert at the same speed (8.3-8.4h median) because they're both governed by the same Paxos response.

## Methodology lesson #16 (CANDIDATE) — Meth #14 has a stable-class boundary

**Cross-venue coincidence has signal value only when redemption arb pathways are venue-distributed.**

Two stable-class regimes:
1. **Distributed-redemption stables** (USDe, USDD, TUSD, USDP, FDUSD, USDC):
   - Per-venue dollar rails OR per-chain bridge mechanisms
   - SOLO depegs = single-venue orderbook noise → fast revert
   - CONFIRMED depegs = systemic stress on multiple rails simultaneously → slow revert
   - **APPLY Meth #14 (SOLO is higher-quality tier)**
2. **Centralized-redemption stables** (PYUSD, possibly future regulated issuers):
   - Unified B2B desk handles all arbs
   - SOLO ≈ CONFIRMED structurally (same desk responds the same way)
   - **DO NOT APPLY Meth #14 (SOLOFLAG filter = pure throughput loss)**

To classify a new stable: look at the issuer's published arb mechanism. If it routes through a single B2B desk with uniform capacity → centralized. If venue-specific or chain-specific → distributed.

The PYUSD-Paxos B2B desk classification matches publicly known operational details (Paxos publishes a daily redemption schedule for institutional clients; max ticket size $10M+; turnaround T+0 to T+1).

Filing this as candidate Methodology #16. To upgrade from candidate → canonical we'd need a second corroborating instance. RLUSD (Ripple, regulated, B2B desk operated by Ripple itself) would be a natural candidate but had no events in our 12mo universe at 50bp tier (need to wait for one or expand to 25bp tier).
