## Method

1. Reload `/tmp/h3_klines_24mo.parquet` (1,255,187 5m bars, 6 stable/USDT pairs, 24mo) and `/tmp/h3_events_24mo.parquet` (150 events).
2. For each event, compute three gates:
   - **G1**: entry-bar `vol > 0`
   - **G2**: G1 + `≥2 of last 6 bars have vol > 0` (≥2 active bars in past 30min)
   - **G3**: G2 + entry-bar `notional = vol × close ≥ $500`
3. Sensitivity sweep: notional floors {0, 10, 50, 100, 500, 1000} × active-bar floors {0, 1, 2, 3}.
4. Characterize **phantom prints** = `notional < $100 AND active_30min_pre ≤ 1` (isolated wick on dead tape).
5. Recommended operational gates: G_paper (notional≥$10 + NOT phantom), G_live100 (notional≥$100), G_live1k (notional≥$1000).
6. Re-run walk-fwd, per-(ex,sym), per-month, per-magnitude under G_paper.
7. Stress slip 40/80/120bp.

## Practical paper-stream spec update — graduated vol gate

The right vol gate depends on deployment size, not a fixed dollar floor. New **Methodology #13.1 — graduated vol gate**:

- **For paper at $1 size (initial validation)**: `entry_notional ≥ $10 AND NOT phantom` (where phantom = notional < $100 + ≤1 active 30min pre). Captures n=129 / 50bp / +0.81% mean.
- **For live at $100 size**: `entry_notional ≥ $100`. Captures n=112 / 50bp / +0.85% mean.
- **For live at $1000+ size**: `entry_notional ≥ $1000` + WebSocket L2 verification at entry-time. Captures n=73 / 50bp / +0.99% mean.

This replaces the fixed "$500 floor" from cycle_1132's first cut. Reason: the $500 floor was a rough heuristic; it removes legitimate small-notional events (KuCoin USDD has 73 events with median notional $410, all WR 97%, all real depegs) while still allowing low-quality phantoms past via the "active bars" pathway. The phantom criterion (notional<$100 + isolated) is the cleaner discriminator.

For live deployment at $100 notional: there is **$10-$50 notional headroom per event** between paper-validated coverage and live-executable coverage. Should be fine in practice (price wouldn't move materially on a $100 order against a $400 prior-bar quote), but for $1k+ size the operational tier should be 75bp/G_live1k (n=30, +1.91%, WR 100%, Sharpe 0.84).

## Methodology lesson #13 — refined to #13.1

**Vol gate at trigger layer should scale with intended deployment size.** A single fixed dollar floor (originally proposed as $500 in cycle_1132) is wrong-direction conservative for paper validation (drops legitimate thin-but-real events at $1 paper-size) and wrong-direction permissive for live-at-scale (some events that pass $500 floor still aren't tradable at $10k).

**Operational definition**:
- `phantom_print = (entry_notional < $100) AND (active_30min_pre ≤ 1)` — isolated wick on dead tape. Always exclude.
- `paper_safe = entry_notional ≥ $10 AND NOT phantom_print` — fine for $1 paper-size validation.
- `live_safe(size) = entry_notional ≥ max($100, size × 10)` — 10× safety factor over intended notional.

This refinement preserves Methodology #13's spirit (don't trust ghost wicks) while correctly scaling the gate to the test/deployment context.
