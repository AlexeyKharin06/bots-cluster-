## (4) Permutation null — the decisive number

I replicated the pipeline's selection power (1-way exhaustive + 2-way + 120K random 3-way on the same quantile thresholds) with survivor criteria mirroring STRICT **plus a simplified walk-forward gate** (time-split 70/30: TRAIN mean>0 AND TEST n≥3 with WR≥90% & mean>0, in-sample n≥18 & WR=100% & mean≥1%). Then shuffled the PnL labels across the 101 events and re-ran (12 shuffles):

```
REAL  survivors passing STRICT-lite + walk-forward: 520   (281 distinct event-sets)
NULL (12 PnL shuffles): mean=145  median=68  min=16  max=392
```

**Under pure noise, the SAME pipeline yields a median of ~68 "STRICT-WF-validated" filters (up to 392).** The walk-forward TEST gate does NOT remove false discoveries, because the TEST window is reused as a *selection criterion* across millions of candidates — the test set becomes part of the optimization. Real (520) exceeds null (68), which only confirms there IS real structure in these 101 events (we knew that — H34 is a validated edge with an 89%-WR rank==1 tier). It does **not** validate any specific +2%/100%-WR/Sharpe-4 "edge": those headline stats are artifacts of picking the best ~18 of 101, and the bootstrap-CI-lower-bound≥1% is computed on the *selected* sample → circular.

## METHODOLOGY #30 CANDIDATE (filed)
**Walk-forward applied as a SELECTION filter across a large candidate set provides no out-of-sample protection.** When the same time-split TEST window is used to choose among millions of filters, the TEST window becomes part of the optimization and "TEST mean > 0 / TEST WR ≥ 90%" passes by chance for many candidates. Likewise a bootstrap CI computed on the *selected* sample is circular. To honestly validate a mega-grid output you MUST either (a) hold out a window that is NEVER touched during any selection step, or (b) measure the false-discovery floor with a permutation/label-shuffle null and require the real survivor count / effect size to exceed that null by a wide, quantified margin. Corroboration #1 = this cycle (null floor 68 "validated" filters on shuffled H34 PnL). This subsumes the project's long-standing survivorship-bias vigilance into a concrete FDR procedure for any future `*_megasearch`.

This is NOT a criticism of running the megasearch — broad search is a legitimate hypothesis generator, and it usefully re-confirmed the dispersion mechanism. The lesson is purely about how to *read* its output: the catalog is a list of hypotheses, not a list of edges.
