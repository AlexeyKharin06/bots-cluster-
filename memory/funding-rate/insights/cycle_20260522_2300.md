## Method

The parquet contains POSTED funding events (one row per funding payment). Premium-index minute-level data not available in stored parquet. So "cross-ex formula divergence" reformulated as **cross-ex REALIZED-RATE divergence** at hourly buckets:

1. Bucket each posting into 1h windows (`ts_bucket = ts // 3600000 * 3600000`).
2. For each `(sym_norm, ts_bucket, exchange)` take LAST rate in bucket.
3. Pivot to wide: `(sym, hour) × [binance, bybit, gate, bitget, okx, hyperliquid]`.
4. Divergence = `max(rate) - min(rate)` across exchanges where ≥2 have rates in that bucket.
5. Divergence event = `div ≥ threshold` (tested 30/50/75/100/150/200bp).
6. Recompute interval-shortenings directly from parquet (gap-on-same-(ex,sym)): **213 events** (matches H31 known count).
7. For each divergence event, check whether ANY shortening on same sym follows within [T, T+24h].
8. Baseline: random (sym, hour) with ≥2 ex sampled n=5000, same window check.
9. Walk-fwd: TRAIN < ts_q70 = 2026-03-08 17:00 UTC, TEST ≥ ts_q70.

## Time-to-event distribution (the crucial question)

Of 197 (sym, hour) divergence-event → shortening pairs:

| Lead window | n | %  |
|---|---|---|
| 0-1h (coincident) | 127 | 64.5% |
| 1-2h | 32 | 16.2% |
| 2-4h | 22 | 11.2% |
| 4-8h | 66/197 → 33% cumulative at 4h+ |

**64% of "hits" are coincident (≤1h lead).** This means the divergence signal is largely concurrent with the event — picks up the exchange that ALREADY shortened relative to peers — not truly predictive at <1h.

## Verdict on Edge 3 status

**NOT Edge 3 — mechanism overlaps H31.** Reasoning:

1. **Symbol overlap is extreme.** Of 88 unique syms with ≥50bp divergence, ~50 are also in H31 events. The chronic-discount cluster (RIVER, DRIFT, RAVE, SIREN, PIPPIN, ENSO, ORCA, FLOW, KITE, AXS) drives BOTH the divergence signal AND most H31 events. Same regime, same population.

2. **Coincident hits dominate.** 64% of divergence→shortening matches happen within 1h. The divergence is largely a REAL-TIME indicator that "the shortening just happened on one ex, hasn't propagated to others." That's downstream of the event, not predictive.

3. **Predictive lead degrades precision.** At 4h-24h lead, precision is 6.6% TEST. Even with 16x lift, expected PnL per signal at the H31 success rate (+3.45%/event basis-hedge): 0.066 × +3.45% = **+23bp/signal gross**. After slippage and the operational cost of monitoring 1225 signals to catch 88 events, net edge is marginal.

4. **As a direct trade, divergence ≡ H34 perp-perp entry.** If binance rate = −80bp and okx rate = +20bp on same coin same minute, the natural trade is LONG-binance-perp + SHORT-okx-perp = exactly H34's perp-perp hedge mechanism. That's already Edge 2. Divergence as direct trade re-creates known edge, not new mechanism.

5. **Recall is modest.** Only 27% of H31 events have an advance divergence signal. The remaining 73% are not predicted by C2 — so even as an early-warning system, C2 catches only a quarter of the H31 universe.

**Catalog status:** C2 = **WIDER H31 / H34 DETECTOR**, NOT independent Edge 3. Methodology same family as C8/H38 — a correlated regime detector, not a new physics.

## What C2 IS operationally useful for

- **Real-time monitor** running on incoming funding postings: flag any (sym, time) where cross-ex `max - min` ≥ 50bp on ≥2 exchanges → triggers H34-style perp-perp hedge with 16% probability of confirmed H31 event in 24h.
- **OKX-pair filter** lifts precision: binance×OKX 37%, bybit×OKX 33%, bitget×OKX 32%. Filtering to OKX-involving pairs only would reduce signal count from 1225 → ~400 but raise precision from 16% to ~30%.

## Methodology lesson #10

**Cross-exchange divergence on the same instrument is not orthogonal to single-exchange funding stress — they're two views of the same regime.** When one venue starts pricing different from peers on a chronic-discount coin, it's reacting to the same one-sided OI crowding that produced the deep funding in the first place. Genuine Edge 3 needs a DIFFERENT regime trigger (depeg event, on-chain flow, exogenous shock), not a different vantage on funding stress.

Adding to procedural memory: orthogonal mechanism > orthogonal signal > orthogonal data source. C2 was at level "orthogonal signal" (cross-ex view) but failed mechanism-orthogonality.

## Operational follow-ups for monitoring (not Edge 3, but useful)
