## Mission

BRIEF (set last cycle 20260522_1009) flagged H37 (the practitioner premium-index predictive
funding-scalp formula) as the highest-EV remaining candidate for the missing Edge 3 — the
last KPI 4 blocker. KPIs 1-3 (walk-forward mean>0, WR≥75%, DD≤15%) are all green; only

This cycle: retrospective test of the practitioner formula on Binance fapi historical data.

## Method

For each historical Binance funding event T with `|realized rate| ≥ 30bp` (large enough
that net edge after slippage could plausibly exist):

1. **Fetch premium-index klines** (`/fapi/v1/premiumIndexKlines`, 1m, 60 bars, ending T-1m).
2. **Compute predicted funding** via the practitioner formula (de-obfuscated from
   `Info/files/module.js`):
   ```
   weighted_avg = Σ(w_i × premium_i) / Σ w_i,   where w_i = 6 + 12·i   (recency-weighted)
   funding_predicted = weighted_avg + clamp(interest − weighted_avg, ±0.05%)
   ```
   `interest` = 0.0001 (binance default for USDT pairs).
3. **Fetch 1m price klines** for [T−5m, T+5m] (10 bars).
4. **Strategy** (honest, no oracle): take the funding-receiver side at T−60s
   (LONG if predicted < 0, SHORT if predicted > 0); exit at T+60s.
5. **PnL** = funding_received − price_drift − 4bp round-trip slippage
   (binance taker = 2bp/leg).

Sample: 150 events sampled uniformly from the 2,381 events with |rate| ∈ [30bp, 150bp].
The clamp-at-200bp events were excluded (extreme outliers; they correlate with cascading
liquidations that distort price drift). All fetches succeeded — 0 failures.

## Why does this fail despite 98% accurate prediction?

Diagnostic on the same 150 events:

| metric | bp |
|---|---|
| Mean \|funding received\| | **55.4** |
| Median \|funding received\| | 46.2 |
| Mean \|price drift\| in ±60s | **95.8** ← larger than funding |
| Median \|price drift\| | 69.0 |
| p95 \|price drift\| | 285.6 |
| corr(funding_recv_bp, price_pnl_bp) | **−0.20** |
| % trades where \|funding\| > \|drift\| | **38.7%** |

In a 2-minute window around a large-funding event, price routinely moves more than the
funding receipt. The price-drift is modestly anti-correlated with funding direction
(−0.20): when funding is deeply negative (shorts pay longs), the asset is being shorted
heavily → spot/perp is falling → going LONG to receive funding pays for ~half of it back
in lost mark-to-market. **In 61% of events the drift exceeds the funding magnitude.**

## Decision

**H37 as unhedged funding scalp: REJECTED.** (catalogued as R15.)

Logged reasons:
1. Sharpe 0.12 in-sample is below any acceptable threshold (need Sharpe ≥1.0 for paper).
2. Walk-forward TRAIN +6 / TEST +38 with no signal: 8x ratio = noise pocket, same flavor
   as R14 (H31 unhedged).
3. Structural: median price drift (69bp) > median funding (46bp); only 39% of events have
   funding > drift. No selection rule can deterministically pick the 39%.
4. Negative drift correlation (−0.20) is unhelpful but not catastrophic — even if drift
   were uncorrelated, magnitude alone disqualifies.

## What WOULD work — and is NOT a new edge

A **basis-hedged** variant of H37 (LONG perp + SHORT spot, or LONG perp + SHORT perp on
2nd exchange) eliminates the drift dependency entirely. That's a 2x larger trigger
universe for the H31/H34 stack (7,914 events with |rate|≥10bp vs 116 H31-shortening
events). BUT:

- It's the same mechanism as H31_basis_hedged.
- Correlation between "interval-shortening triggered basis hedge" and "magnitude-triggered
  basis hedge" is necessarily high — both fire on overlapping funding-stress regimes.
- It would NOT increment the independent-edges count (KPI 4).
- It WOULD strengthen H31 by ~37x event throughput → that's interesting for sizing, not
  for edge-count.

Flagging this as **H38** (catalogue, not Edge 3): "Magnitude-triggered basis-hedge
expansion of H31." Test next cycle: re-run H31's net basis PnL but on the 7,914 high-|rate|
events instead of the 116 interval-shortening events. If WR remains ≥85% on the expansion
set, this is a throughput improvement for H31 (more trades, lower per-trade size).

## Caveats / honest limitations

1. **1m kline granularity.** Entry at T-60s, exit at T+60s — coarser than the practitioner
   strategy implies (T-30s to T+30s). Tighter windows would reduce price drift but Binance
   futures klines bottom out at 1m. AggTrades-level reconstruction is possible but expensive
   (~10K aggTrades / event × 150 events = wasn't worth time-budget).

2. **Slippage assumption.** 4bp round-trip is realistic for taker fills on majors at
   reasonable size. For the smaller symbols in the 30-150bp universe (PIPPIN, SAHARA, etc.)
   at thin notional this could underestimate slip by 5-15bp. Doesn't change the conclusion
   — even 0bp slip wouldn't lift Sharpe past 0.15.

3. **n=150.** Modest sample. Could 3x with full universe (would consume more API calls).
   Won't change directional conclusion given existing variance.

4. **Skip-of-clamp-200bp events.** I excluded |rate|≥150bp events under the assumption
   they're price-cascading outliers. Sensitivity check on the 354 |rate|>100bp events
   shows mean drift exceeds 200bp on average — would have made the result worse, not
   better. Conclusion robust.

5. **Predicted-direction strategy ≈ realized-direction strategy in this regime.** Because
   the formula is 98% accurate, conditioning on predicted vs realized matters only at the
   margin. Honest implementation is the standard for KPI evaluation.

## Methodological lesson

Adding to the running catalogue of methodology fixes (procedural memory):

> **Lesson #8: Predicting a funding rate accurately is not the same as having a tradeable
> edge.** The mechanism that produces large funding (one-sided OI crowding) is also the
> mechanism that produces price drift in the same direction. Predicting funding magnitude
> can be 98% accurate while net unhedged PnL is zero. Edge exists only if you hedge the
> price risk — at which point you've recreated H31/H34, not a new mechanism. Test for
> orthogonal mechanism, not orthogonal trigger.

## Other observations

- **Premium-index klines endpoint exists** and is well-behaved on Binance futures —
  worth using as a real-time feed source in production. Field 4 ('close' of bar) IS the
  closing premium, in fractional form (e.g. `0.0003` = 30bp).
- **Binance interest rate** defaults to 0.0001 per 8h interval for USDT pairs. Verified
  by inspecting the practitioner module config.
- **`/fapi/v1/klines` does NOT support `interval=1s`** — returns HTTP 400. Only `1m+` is
  available. For sub-minute timing, need aggTrades or the websocket book-ticker stream.
- The 200 candidate symbols' funding intervals in our parquet are heterogeneous: many of
  the smaller ones are 1h (interval-shortened) rather than 8h. The 1m=60-bar premium
  window is appropriate for all of them since premium-index is sampled per-minute by
  Binance regardless.
