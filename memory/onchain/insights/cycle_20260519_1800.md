Same-token-in-many-streams is **structural**: the sniper records one logical detection but emits one closed_trade row per matching stream. The streams are tag-overlapping filters on the same opportunity.

Then ran `dedupe_history.js` across the entire 8-day dataset:

- **ALL rows: 4999, unique tokens: 683, avg dup ratio: 7.32**
- Per-hour dup ratios range 3.86 → 10.50 (rising over time — more streams active recently).

### Implication

Every prior cycle's analysis used row-based aggregates that were 7-10× inflated by stream tag duplication. This does NOT trivially invalidate per-feature filter findings, BUT for any per-wallet whitelist (e.g. H_LP_WHITELIST that required `n≥3` per LP), the "n≥3" threshold was being satisfied by ONE token caught by 7+ streams. The "24-wallet TRAIN whitelist" from cycle_1639 likely included many single-token wallets where the wallet looked successful only because of duplication.

This is a separate leakage form from hindsight-classifier (cycle_1702): a **counting inflation** that makes statistical thresholds spuriously easy to clear and inflates apparent edge by giving a single token multiple "trades worth" of weight.

## Step 10 — methodology lessons accumulated

1. **Per-token is the correct unit for filter analysis.** Use per-token dedup for all wallet-leaderboard and "n≥k" constructions going forward.
2. **Frozen-at-entry features (`entry_signal.lp_hist`, `cr_hist`) are leak-safe** — duplication inflates the count but each unique token has its own correct snapshot.
3. **Two distinct leakage forms now catalogued**:
   - **Hindsight classifier** (cycle_1702 H_RUG_PC): external DB built with future info.
   - **Counting inflation** (this cycle H_LP_WHITELIST): row-based stats over multi-stream-tagged data inflate confidence thresholds.
4. **Macro regime can mask real signals.** Current last-12h baseline -73% destroys all known filters. Either ride it out, pause paper streams, or build a "regime guard" filter (don't trade when rolling-N baseline < -X%).
